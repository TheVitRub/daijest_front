# Декомпозиция app.js + перевод на делегирование событий

**Дата:** 2026-06-23
**Ветка:** `refactor/app-js`
**Статус:** дизайн утверждён, ожидает вычитки спеки

## Контекст и цель

`daijest_front/app.js` — один файл на ~2663 строки: конфиг, глобальное состояние
(~60 модульных `let`), персист, авторизация, админка, проекты/ревизии, drag&drop,
рендер редактора и превью, экспорт (PNG/PDF/JSON). UI собирается конкатенацией
строк HTML с inline-обработчиками (`onclick="foo()"`), которые ссылаются на
глобальные функции.

Цель: разложить код на изолированные ES-модули и перевести inline-обработчики на
делегирование событий (вариант B). Деплоя нет — проверка локально через
`docker-compose`, решение о вливании в `main` принимает пользователь.

### Ключевые факты, влияющие на дизайн

- **96 inline-обработчиков** в генерируемом HTML внутри `app.js` + ~6 в
  `digest-builder.html`. Все зовут глобальные функции.
- **`logo-data.js` — осиротевший файл**: не подключён ни в одном HTML, `LOGO_DATA`
  нигде в коде не используется. Экспорт берёт логотипы через `fetch('logos/*.svg')`
  (`svgImageToDataUrl`). Прежняя заметка «LOGO_DATA must stay» устарела. Файл **не
  трогаем и не удаляем**, только коммитим в историю.
- Автотестов нет. Экспорт PNG/PDF хрупкий и подогнан вручную (PDF намеренно
  переиспользует PNG-пайплайн `pageToDataUrl @ scale 3`). Логику экспорта при
  переносе **не меняем**.
- Сторонние библиотеки (`html2canvas`, `jszip`, `jspdf`) грузятся как глобальные
  classic-скрипты. Модули обращаются к ним через `window.*` — это сохраняется.

### Известные баги (из код-ревью), чинятся в Фазе 1

1. `toggleAdminRole` и `saveAdminEditName` обращаются с результатом `apiRequest`
   как с `Response` и зовут `.json()` — каждый вызов падает. Назначение
   админа/сохранение имени не работают.
2. Мёртвый код: `adminEditOpenId` никогда не выставляется в truthy; глобальный
   обработчик кликов в `init` впустую гоняет `render()`.
3. `getElementById(...).addEventListener` при загрузке без null-проверок
   (`fileInput`, `companyFileInput`, IIFE ресайза) — одна правка вёрстки роняет
   весь скрипт.

## Безопасность

- Вся работа в ветке `refactor/app-js`. `main` не трогаем — это точка отката.
- `logo-data.js` коммитим в историю (был вне git).
- Без деплоя. В удалённый репозиторий ничего не пушим без отдельной команды.
- Проверка после каждой фазы через `docker-compose`.

## Порядок работы (фазы)

Каждая фаза — отдельный коммит после локальной проверки. К финалу B идём через
рабочее состояние A, чтобы на каждом шаге был чекпойнт для отката.

### Фаза 1 — починка багов (на текущем монолите)
Чиним три бага выше, не меняя структуру файла. Изолированно и проверяемо.
→ проверка → коммит.

### Фаза 2 — разрезать на модули, обработчики НЕ трогаем
Разносим код по модулям (см. структуру ниже). `main.js` импортирует всё и
временно вешает функции-обработчики на `window` (промежуточное состояние = вариант
A). Поведение не меняется, inline `onclick` продолжают работать.
→ проверка → коммит.

### Фаза 3 — перевод на делегирование событий (это и есть B)
Все 96 inline-обработчиков в генерируемом HTML + ~6 в `digest-builder.html`
переводим на `data-action` + `data-*`. Временный мост в `window` убираем.
→ проверка → коммит.

### Фаза 4 — мелкая чистка качества
- Полное экранирование (`& < > " '`) вместо текущих частичных `escAttr`/`escText`.
- Статусы сохранения через коды/enum вместо поиска по русским подстрокам.
- Убрать дублирование (fallback метрик, SVG-иконки, повтор паттернов).
- Унифицировать подтверждения (везде кастомный диалог вместо смеси `confirm`/без).
→ проверка → коммит.

## Структура модулей

Папка `js/`, точка входа `main.js`. В HTML:
`<script type="module" src="js/main.js?v=N">`.

- `config.js` — `STORAGE_KEY` и пр., `COMPANIES`, `BLOCK_TYPES`, `API_BASE`,
  `PUBLIC_BASE_PATH`
- `dom/escape.js` — корректный `escapeHtml`
- `dom/icons.js` — SVG-иконки (chevron, drag-handle, стрелки, корзина и т.д.)
- `state/state.js` — объект `state`, геттеры (`getComp`, `getBlock`), мутации
  блоков/айтемов/метрик
- `state/history.js` — снапшоты, undo/redo
- `storage.js` — `safeStorage*`, локальный черновик, конверты состояния
- `api.js` — `apiRequest`, сессия/токен
- `features/auth.js` — экран входа
- `features/projects.js` — CRUD дайджестов, ревизии, откат, переименование
- `features/admin.js` — админ-панель
- `features/import-export.js` — импорт/экспорт JSON (проект и компания)
- `features/media-export.js` — PNG/PDF, инлайнинг SVG (**логику не меняем**)
- `dnd.js` — drag&drop блоков, айтемов, группы метрик
- `view/editor.js` — рендер редактора (компании/блоки/айтемы/письмо)
- `view/preview.js` — рендер превью (страницы дайджеста)
- `view/account.js` — аккаунт-бар, шторка проектов, диалоги, админ-секция
- `view/status.js` — статус сохранения (enum + отображение)
- `render.js` — оркестрация (`render`, частичные апдейты)
- `actions.js` — таблица «имя действия → функция-обработчик»
- `events.js` — навешивание делегированных слушателей
- `main.js` — точка входа, `init`

Принцип: каждый модуль имеет одну зону ответственности, общается через явные
импорты/экспорты, его можно понять и проверить отдельно.

## Делегирование событий (механика Фазы 3)

Вместо `onclick="openProject('id123')"` элемент несёт
`data-action="open-project" data-id="id123"`. На корневом контейнере висят
слушатели на `click`, `input`, `change`, `submit`, `keydown` и drag-события.
Слушатель читает `data-action`, находит функцию в таблице `actions.js` и вызывает
её, передавая распарсенные `data-*` (compKey, blockId, idx, field, tile и т.п.) и
сам элемент/событие.

Особые случаи, требующие внимания при переводе:
- **Составные обработчики** вида
  `oninput="updateLetterField('title',this.value);...textContent=this.value.length+'/200'"`
  — счётчик символов централизуем: `data-counter="<id>"` + `data-max="200"`,
  диспетчер обновляет состояние и счётчик.
- **Клавиши**: `onkeydown="if(event.key==='Enter')...; if(Escape)..."` →
  действие + проверка `event.key` в обработчике.
- **Drag&drop**: `data-action` + чтение `data-*` с цели; `dataTransfer` берём из
  события. Drag-хэндлы (`onmousedown=...draggable=true`) переводим на делегирование
  с переключением `draggable` у ближайшего родителя.
- **Бэкдроп-клики** (`onclick="if(event.target===this)close()"`) → проверка
  `event.target === event.currentTarget` в обработчике.

## Стратегия проверки (после каждой фазы)

Поднять `docker-compose`, открыть конструктор и прогнать вручную:
- вход по коду доступа; список проектов загружается;
- создание/переименование/дублирование/удаление проекта;
- добавление блоков и айтемов (новость и метрика), редактирование полей,
  счётчики символов;
- drag&drop блоков, айтемов, группы метрик;
- загрузка обложек и фото; выбор соотношения сторон;
- undo/redo; автосохранение и ручное сохранение; история версий, просмотр и откат;
- импорт/экспорт JSON (проект и компания);
- админка: создание пользователя, назначение/снятие админа, правка имени,
  удаление (особенно бывшие баги из Фазы 1);
- экспорт PNG (zip) и PDF — визуально сверить с результатом на `main`.

## Вне рамок (YAGNI)

- Переезд на фреймворк/реактивность — нет.
- Локальные ре-рендеры по секциям вместо полного `render()` — отдельная будущая
  задача, в этот рефактор не входит.
- Изменение логики экспорта PNG/PDF — нет, только перенос «как есть».
- Сборщик/бандлер — нет, нативные ES-модули по http через nginx.
